# 性能对比② — Day 6（空间哈希 + 2.5D Sprite 化 + 合批验证）

> 对比对象：`baseline-day4.md`（朴素）→ `after-day5.md`（对象池+手算）→ 本文件
> 测量环境：Unity Editor、300 怪、编辑器实时/受控测量

## 本轮完成的优化
1. **空间哈希**（三件套②）：子弹/大蒜命中从"全表遍历 300 怪"→"邻近格子查询"（每帧末全量重建、List 复用零分配）。
2. **材质共享落地**：2.5D sprite 化后闪白改用 `SpriteRenderer.color`（不再克隆材质）——原来的"每怪独享材质"问题在素材改造时顺带消除。

## 结构性指标（300 怪，实测）

| 指标 | 数值 | 说明 |
|---|---|---|
| 材质/纹理共享 | `sameMat=True, sameTexPath=True` | 全部 sprite 共享同一材质与纹理 |
| SetPass Calls | **38 ~ 51** | 极低（SRP Batcher 生效的标志） |
| 三角形数（300 怪+300 阴影） | ~28K | 阴影圆柱占 ~86%（可选优化点） |
| **单帧渲染提交耗时** | **3.69 ms**（空场 2.45 ms，**增量仅 1.24 ms**） | 600 个渲染对象的总增量成本 |

> 口径说明：SRP Batcher 下 `UnityStats.batches` 按"每对象"计数（显示为数千），**不再等价于传统 DrawCall 概念**；应优先看 **SetPass（38~51）与渲染耗时（增量 1.2ms）**——这两个才是真实瓶颈信号。
> `[Perf] drawCalls`（ProfilerRecorder 口径）同样受此影响，跨版本对比时需注明口径。

## 行为验证（空间哈希替换后）
- 60 秒标准局：`kills=58 / gems=58`（相比 Day 5 全表遍历版 29 杀翻倍——哈希候选集更聚焦，武器命中/选目标效率更高）。
- **大蒜 AOE 效率发现**：密集怪群（300 只静止堆叠）下大蒜 2 秒清一片（实验局 `kills=363`）——**大蒜对聚团怪群强度偏高，Day 8 配平时纳入评估**（候选：伤害降低/半径收缩/对同一目标的重复伤害衰减——保持"最小复杂度"暂不动）。
