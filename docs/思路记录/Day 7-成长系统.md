# Day 7 思路记录 — 成长系统（经验/升级三选一）

> 对应代码：`LevelSystem`（新增·核心）、`LevelUpPanel`（新增·UI）、`WeaponGrenade`+`Grenade`（新增·手雷）、`ExperienceGem`（拾取）、`PlayerStats`/`WeaponBase`/`WeaponKnife`（升级接口）
> 重做对照难度：★★★★☆（系统本身不复杂；值得学的是"选项池 + 直接改字段"的最小化设计）

## 今天做了什么

1. **成长闭环**：宝石拾取 → 经验累积 → 满经验升级（时停）→ 三选一面板 → 点击应用 → 恢复游戏。
2. **升级池**（按用户口述需求）：飞刀（伤害/射速/多重/满级进化弩枪）+ 大蒜（伤害/半径）+ 手雷（新武器获取 + 伤害）+ 4 种被动（攻击/移速/生命/拾取）。
3. **大蒜/手雷改为升级获取**（开局只带飞刀）——宝石从"没用的蓝方块"变成变强燃料。
4. 拾取手感：吸附范围 2.5m → **3.5m**（站桩测试中宝石在 2.58m 外吸不到的教训）。

## 关键设计与取舍

### 1. "升级项 = 标题 + 描述 + Apply 委托"（最小复杂度）
- 不引 ScriptableObject、不做配置文件：每个选项就是 `new UpgradeOption { Title, Desc, Apply = () => ... }`。
- **Apply 直接修改武器/玩家字段**（如 `_knife.AddDamage(5f)`）——"升级"落地为"改数字"，一眼看懂。
- 上限控制用简单的计数器字段（`_knifeDmg < 3`），也是"防超选"的开关。

### 2. 候选池生成 = 一串 if（可读性优先）
- 遍历所有"可升级项"（未满级/未获得/进化条件满足）→ 等权随机 3 个不重复。
- 拒绝"权重表/稀有度"等复杂设计——先跑通最小闭环，权重是 Day 8+ 的调参话题。

### 3. 武器侧提供"升级接口"保持封装
- 初版 LevelSystem 直接改 `Damage/Cooldown`（编译报错：protected）——顺势改为 `AddDamage/AddCooldown/AddRange` 三个公共方法：
  既解决跨类访问，又把"升级"语义显式化（调用处一眼看出"这是在升级"）。

### 4. 面板交互的关键细节
- 全屏半透明遮罩 Image：既是视觉蒙层，**又是输入拦截器**（挡住下层摇杆，防止点击穿透）。
- 面板在 Canvas 中最后添加 → 渲染最上；时停由 GameManager 统一控制（EnterLevelUp/Resume）。

### 5. 手雷的实现：飞行体 + 到达爆炸
- `WeaponGrenade` 只负责"选目标 + 发射"（复用武器基类的锁定/索敌）；`Grenade` 负责飞行与爆炸（AOE 走空间哈希查询）。
- 爆炸把怪向外击退（方向 = 从爆点指向怪）——视觉与机制一致。

## 踩的坑

### 1. 跨类访问 protected 字段
- `LevelSystem` 直接改 `_knife.Damage` → CS0122。修复：武器提供公共升级接口（见上）。

### 2. "站桩测试"暴露的拾取范围问题
- 验证时发现 131 击杀但等级不动：宝石全部落在 2.58m 外（飞刀杀的怪大多死在远处），吸附范围 2.5m 差一点点。
- **不是 bug 但暴露数值问题**：真实游玩中宝石也会"堆在远处捡不到"→ 范围调到 3.5m。
- **测试方法 refinements**：站桩验证"拾取系统"不可靠（要模拟走位）——用"瞬移到最近宝石 + 推帧"模拟玩家捡宝石。

## 验证证据（全链路自动化）
- **升级流程**：模拟走位拾取 → 连续升级；`[R0:Lv2选多重射击][R1:Lv3选移速]` 实测生效（多重 1→2、移速 ×1.1）。
- **获取型升级**：Lv4 选"获得手雷"、Lv5 选"获得大蒜" → 组件成功追加（`蒜=True 雷=True`）。
- **新武器实战**：6 只怪在场推帧 6 秒——手雷飞行体出现 ✓、kills +11（大蒜光环 + 手雷爆炸联动）✓。
- 编译零错误；全程 state 机正常（Playing ↔ LevelUp ↔ Resume）。
