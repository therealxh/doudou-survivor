# Day 8 思路记录 — 配平与特效（第一轮）

> 对应用户试玩反馈：手雷频率/爆炸范围/升级节奏/怪物成长/爆炸表现
> 本轮为"数值手术 + 补特效"，全部改动有明确反馈依据

## 本轮改动清单

| 用户反馈 | 改动 | 依据/思路 |
|---|---|---|
| 手雷投掷频率要降低 | 冷却 2s → **3.5s** | 手雷是"大威力"武器，间隔拉长才能体现权重 |
| 爆炸范围太小 | 判定半径 2m → **3m** | 3m ≈ 半个屏幕高，能覆盖一个怪群 |
| 升级节奏太快 | 门槛 `5+(L−1)×3` → **`12+(L−1)×8`** | 原版 5 杀升级太快（约 10 秒一级）；新区间让升级成为"阶段性事件" |
| 怪物成长太慢 | HP 曲线 1.1 → **1.15/分钟**；刷怪加速 0.1 → **0.12/分钟** | 玩家成长（升级/进化/AOE）提速后，怪也必须提速，后期才有压力 |
| 爆炸没有明显效果 | 新增 **BlastEffect 爆炸圈**（扩散渐隐 0.35s） | 此前只有伤害、没有表现——"看不见的伤害等于没有打击感" |

## 爆炸特效实现要点
- 复用素材流水线（AI 生成爆炸图 → art-process.py 抠图）→ `Resources/Sprites/explosion.png`。
- `BlastEffect`：平躺贴地、0.7x → 1.15x 判定直径扩散、alpha 线性渐隐；池化复用（预热 8）。
- 与伤害数值的关系：视觉 0.7x 起步 → 结束时略大于判定圈（观感与判定"体感一致"）。

## 验证证据
- 爆炸视觉第 13 步出现（手雷 0s 首发）；AOE 一次杀 8 只（含 6 只标靶怪）。
- 升级门槛 12 生效：击杀 8 只后仍 Lv1（经验 5/12）。
- 截图存档：`docs/art/爆炸效果预览.png`（大爆炸圈 + 多目标 15 飘字）。
- 编译零错误。

## 第二轮追加（新武器 + 升级幅度细化）

- **弓箭伤害升级 +5 → +3**（用户反馈每级涨幅过高）；大蒜 +3→+2、手雷 +5→+3（统一梯度：主武器每级 +3、副武器 +2~3）。
- **新增武器①环绕飞刃**：绕身旋转（满级 3 把）、每 0.4s 对接触敌人扫击（基础 3 伤）；升级 = 伤害 +2×3 / 数量 +1×2。
  - 视觉教训：细长物"自转"在俯视角下投影太弱（几乎看不见）→ 改为**刀尖朝切向**（旋转刀环感）+ 尺寸 0.5→0.75。
- **新增武器②回旋镖**：向敌人飞出（≤7m）后折返玩家，全程穿透（同趟每怪仅结算一次，HashSet 去重）、基础 8 伤/1.6s；升级 = 伤害 +3×3。
- 验证：环绕 3 把同框 ✓、回旋镖飞出 5.9m 后折返回手 ✓、穿透多杀 ✓（截图 `docs/art/新武器预览.png`）。
- 环境坑记录：验证中途 Play 会话意外退出（静态引用变 destroyed）——诊断 `isPlaying=False` 后重进恢复；**跨 exec 操作前若遇到 MissingReference，先查 isPlaying**。

## 第三轮追加（转速升级 + 大蒜冲击波）

- **环绕飞刃·转速升级**：新增"转速 +25%"升级项（×3，SpeedMult 同步到 Orbiter.OrbitSpeed）——至此环绕飞刃拥有伤害/数量/转速三维修建。
- **大蒜冲击波特效**：每次光环命中有敌人时，以玩家为中心播放青绿纹圈扩散特效（复用 BlastEffect + 双贴图切换）。
  - 实现细节：BlastEffect 泛化为"贴图 + 扩散倍率"参数；冲击波收到判定半径即止（1.0x），爆炸仍超出一圈（1.15x）。
  - **透明度教训**：初版用线性渐隐（1−k）在深色地面上几乎不可见 → 改为 **1−k²**（前中期保持实色）+ 微提亮（×1.15）；另空场不播放（命中才出，避免视觉噪音）。
  - 截图：`docs/art/大蒜冲击波预览.png`（青绿纹圈扩散 + 多目标命中）。

## 重大修复：“游戏卡死”调查（用户报告）

### 症状
用户玩一段时间后游戏“卡死”（编辑器无响应）。

### 调查链路（经典 Debug 案例）
1. **日志取证**：Editor.log 里 [Perf] 显示用户段正常（98fps/12KB），突发中断；无异常/警告日志。
2. **进程取证**：编辑器 Responding=False + CPU 满但内存平稳 → “无分配的纯 CPU 超长循环”特征；等待后自愈（非死锁）。
3. **对照实验**：禁武器/清宝石/清 Console/干净会话 —— 都会 ~10ms/步 → 证实“推帧卡顿”是测试脚本自身（4500 步过长）的假象，排除游戏性能。
4. **真因定位**（重点）：直接模拟 UI 点击路径（RaycastAll）—— 升级面板弹出时，**射线命中链被全屏摇杆层（JoystickArea）独占**，面板按钮完全不在候选——**面板点不动 → 时停无法解除 → 用户视角就是“游戏卡死”**。
   - 根因：UGUI 同 Canvas 内全屏接收层的射线排序压过后续添加的面板（旧代码无排序覆盖）。

### 修复
1. **面板置顶**：面板根加“子 Canvas（overrideSorting + sortingOrder=10）+ 自带 GraphicRaycaster”——标准“弹窗置顶”模式。
2. **摇杆守卫**：FloatingJoystick.OnPointerDown 里 `State != Playing` 时直接 return（时停/结算时摇杆不响应）。

### 验收证据
- 全链射线命中 5 项：按钮文本→Option0→面板根→JoystickArea（按钮在最上）；
- 完整点击路径（RaycastAll → 首命中 → pointerDown/Up/Click）→ 升级应用（Lv2）+ 面板隐藏 + 恢复 Playing。

### 教训（已入交接文档）
- **UI 面板必须“真实点击路径”验收**（RaycastAll 命中链 + 指针事件）——仅代码调 OnPick 会掩盖射线层级的致命问题；
- **全屏接收层（摇杆/遮罩）与弹窗共存时，弹窗必须用“子 Canvas + overrideSorting”置顶**；
- **测试脚本分步执行**（长循环推帧分批，≤1500 步/次），避免“自己造卡死”干扰判断。
